# 共振峰平滑与音频保留设置

## 结论

默认平滑窗口保留 **5 帧**。10 帧更能抑制持续数帧的跟踪毛刺，但并不保证更接近真实共振峰，真实元音变化的响应也更慢。配置页允许输入 **1–30 帧**，每帧间隔 10 ms，设置在下次录音或导入时生效。

音频保留默认为 **20 秒**，配置页允许 **5–120 秒**。两个数字框在按 Enter 或移开焦点后提交，逐键输入的中间值不会改变缓冲。提交后保留时长立即作用于原始采样缓冲、分析帧容量、图表、回放和 WAV 下载；导入上限使用当前设置。缩短保留最新部分，扩大不会补静音或恢复已丢弃的数据。设置保存在本机 localStorage。

## 可复现实验

在 source 目录运行：

```powershell
node node_modules/vitest/vitest.mjs run --project dsp src/__tests__/dsp/smoothing-comparison.test.ts
```

输入是仓库 `assets/a.wav`、`o.wav`、`e.wav`、`i.wav`、`u.wav`、`yu.wav` 及各自的 `info_*.txt` Praat 参考。先用同一混合算法关闭平滑提取原始帧，再分别应用 5 帧、10 帧平滑。稳定段取有效发声帧的 20%–90%，F1、F2 合计计算；下表对六个元音等权平均。

| 指标 | 5 帧 | 10 帧 |
| --- | ---: | ---: |
| 稳定段平均相邻帧变化 | 10.45 Hz | 9.37 Hz |
| 相对 Praat 参考的平均绝对百分比误差 | 3.19% | 3.39% |
| 稳定段较大跳变次数合计，F1 >100 Hz / F2 >200 Hz | 2 | 2 |

10 帧平均变化下降约 10.4%，但参考误差略升；o 元音的平均变化由 9.29 升至 10.69 Hz。较平滑的曲线不等于更准确的测量。

以真实 a 元音分析帧的稳定中位值为基线，仅在分析数据中注入 F1 +400 Hz、F2 +800 Hz 的跟踪毛刺，不生成或修改音频文件：

| 注入毛刺长度 | 5 帧输出受影响帧数 | 10 帧输出受影响帧数 |
| --- | ---: | ---: |
| 1 帧 | 0 | 0 |
| 2 帧 | 0 | 0 |
| 4 帧 | 4 | 0 |

真实变化用两种方式检查：

- 真实 a/i 稳定分析值阶跃：5 帧在 20 ms 后达到新值，10 帧为 50 ms。
- 从真实 a.wav、i.wav 各取中部 0.6 秒，在内存中拼接后重新分析：达到 i 元音范围并连续保持三帧的时间分别为 20 ms、40 ms。

响应按输出帧时间戳计算，不代表麦克风到屏幕的总延迟。这组样本支持保留 5 帧默认值，并为长元音练习提供较大窗口；不推导所有声音上的误差。

## 实现约定与验证

- `src/dsp/formant-smoother.ts` 还包含 50 Hz 死区、300 Hz 跳跃判断和频率顺序保护，并非单纯中值滤波。
- 偶数窗口取中间两项平均；缺失、非有限或非正频率保留为 null 断点。窗口不移动时间戳，元数据保留。
- `AnalysisPipeline` 实时构造参数和静态 `analyze` 第五个参数传递同一个 `formantSmoothingWindow`；旧调用默认仍为 5。
- `RingBuffer.resize` 保持实例身份和最新样本，录制中的后续写入可继续。改变保留时长会停止旧回放快照，下次回放读取新缓冲。
- `src/config/appConfig.ts` 统一整数范围、旧设置补全、坏值恢复；`appStore` 同步缓冲和分析帧容量。
- 回归覆盖偶数中值、空帧断线、实时/导入的帧时间和 register 一致性、录制中缩容、导入期间变更限制、持久化恢复及动态 WAV 长度。
